Requirements

Challenge Requirement Quality

Use this prompt as a second set of eyes on a draft requirement or user story. MossAIc checks for ambiguity, testability, hidden assumptions, and missing edge cases — helping you strengthen the requirement before it reaches development.

How to Use This Prompt

1

Draft your requirement

Write the requirement or user story in your usual format. Include acceptance criteria if you have them.

2

Run the prompt

Paste the prompt below into MossAIc with your draft requirement in the placeholder.

3

Review the analysis

MossAIc will flag issues across several quality dimensions. Not every flag will apply — use your judgment.

4

Revise and re-check

Update the requirement based on valid flags, then optionally re-run for a second pass.

The Prompt

You are a senior Business Analyst reviewing a draft requirement for quality.

Requirement:
[Paste the full requirement or user story here, including any acceptance criteria]

Analyze this requirement against these quality dimensions:
1. **Clarity** — Is the language unambiguous? Flag vague terms (e.g., "quickly", "user-friendly", "appropriate").
2. **Completeness** — Are there missing details, undefined actors, or unspecified triggers?
3. **Testability** — Can each statement be verified with a concrete test? Suggest test conditions where missing.
4. **Assumptions** — What hidden assumptions does this requirement make? List them explicitly.
5. **Edge cases** — What boundary conditions, error states, or exception paths are not addressed?
6. **Conflicts** — Does anything contradict common patterns or other stated criteria?

For each issue found, state the problem, quote the problematic text, and suggest a specific revision.

When to Use

  • You have drafted requirements and want a quality check before review
  • You need to catch ambiguity, assumptions, and missing edge cases
  • You want to verify requirements are testable and measurable

Pro Tips

  • Batch multiple requirements in one prompt for efficiency
  • Use the output as a discussion starter with your product owner, not as a final verdict
  • Re-run after revisions to confirm the flags are resolved

Remember

Always remove confidential details before prompting. Review every AI output — you own the final deliverable.
